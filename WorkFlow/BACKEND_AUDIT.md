## ح-1 — طبقة التحقق وقت التشغيل غير موجودة عملياً

`validators.js` (24,972 بايت، 555 سطر) يُحمَّل في كل فتح للصفحة عبر
`index.html:707`، ويحتوي 22 مدقّقاً — واحداً لكل نشاط.

**الدليل:**
```
$ grep -rn "VALIDATORS\|validateActivityEntry\|validateActivitiesCompleteness" \
    --include=*.js --include=*.html . | grep -v '^./validators.js'
(لا نتائج)

$ grep -n "module.exports\|window.VALIDATORS" validators.js
(لا نتائج)
```

لا مُصدِّر، ولا مستدعٍ. الملف يُحمَّل ولا يُستعمل.
أضف إلى ذلك أن `const VALIDATORS` في نص برمجي كلاسيكي ليس خاصية على `window`،
فحتى لو أراد أحدٌ استدعاءه من `bridge.js` فالوصول ممكن لكن لم يُستعمل قط.

**النتيجة:** العقد بين `bridge.js` والـ renderers غير مُلزَم. كل خطأ شكل بيانات
يظهر كنشاط فارغ أو استثناء في الـ console، لا كخطأ مفهوم.

### لماذا دُفن المحتوى؟ — السبب الحقيقي

شغّلتُ المحوّلات الستة على بيانات الدرس الفعلية. هي **لا تنهار**، لكن مخرجاتها
**خاطئة بيداغوجياً**، وهذا على الأرجح سبب الالتفاف عليها:

| المحوّل | الناتج الفعلي | الخلل |
|---------|---------------|-------|
| traffic-light | عنصران فقط؛ صنّف `أُفَضِّلُ التَّخْيِيمَ عَلَى الشَّاطِئ` كـ `command` | جملة خبرية لا أمر. الاستدلال «إن خلت من لا فهي أمر» غير صحيح لغوياً |
| conjugation-ladder | `{past:"", present:"أُفَضِّلُ"}` | حقل الماضي فارغ دائماً — السلّم بلا درجة أولى |
| punctuation-editor | `{text:"أَيْنَ تُفَضِّلُ لَيْلَى التَّخْيِيم؟", correctMark:"؟"}` | علامة الترقيم ظاهرة في نص السؤال — الإجابة مكشوفة |
| board-game | `"كَثِيرٌ مِنَ النَّاسِ يُفَضِّلُ التَّرْوِيحَ خَارِجَ البُيُو...؟"` | قطع عند 60 حرفاً في منتصف كلمة |
| spot-difference | `{sentenceA:"التَّخْيِيم", sentenceB:"المُخَيَّم"}` | مفردتان لا جملتان — التمرين يفقد غرضه |
| dots-hunter | 5 عناصر سليمة من أصل 6 مطلوبة | مقبول |

**الخلاصة:** المشكلة ليست «أعيدوا الوصل بالمخطط». المحوّلات الاشتقاقية غير كافية
لهذه الأنواع الستة، وهي تحتاج بيانات مؤلَّفة على مستوى الدرس — تماماً كما هو
الحال مع `customWechat` و `customHiddenReveal` اللذين يعملان جيداً.

### المسار المقترح (غير مُنفَّذ — بانتظار القرار)

`resolveData` يدعم أصلاً الرجوع إلى `config.data` عند غياب الحقل
(`bridge.js:183-186`). لذلك يكفي تغيير سطر واحد لكل نشاط:

```js
// قبل
{ id:11, type:"traffic-light", ..., sourceField:"custom", data:[ ... ] }
// بعد
{ id:11, type:"traffic-light", ..., sourceField:"exercises.customTrafficLight", data:[ ... ] }
```

- **سلوك اليوم:** لا يتغيّر إطلاقاً (الحقل غائب → يرجع إلى `data` المدفونة).
- **الدروس الجديدة:** تستطيع تعريف `exercises.customTrafficLight` فتتجاوز الافتراضي.
- **الترحيل:** تدريجي، بلا كسر، وبلا لمس المحوّلات.
- يلزم عندها إضافة الحقول الستة إلى `LESSON_SCHEMA.md` ليصبح المخطط والواقع متطابقين.

## ح-4 — المدقّق يرفض ملفات صالحة

`validate_lesson.js:80`:
```js
const match = raw.match(/const\s+LESSON_DATA\s*=\s*(\{[\s\S]*\})\s*;?\s*$/);
```
`[\s\S]*` جشع ومثبّت بـ `$` بلا راية `m`. أي محتوى بعد الكائن يكسر المطابقة.

**اختباران على نسخة من الدرس الصالح نفسه:**

| المدخل | النتيجة |
|--------|---------|
| الدرس + سطر تعليق في النهاية | ❌ `لم يُعثر على LESSON_DATA object` |
| الدرس + `const LESSON_META_EXTRA = {...}` | ❌ `Unexpected token ';'` |

كلا النمطين شائع في مخرجات الذكاء الاصطناعي. النتيجة رفض كاذب يوقف `generate_lesson.sh`
عند الخطوة 2 ويعطي المؤلّف رسالة خاطئة تماماً عن سبب الرفض.

## ح-5 — تنفيذ كود عشوائي من ملف الدرس

`validate_lesson.js:83` → `data = eval('(' + match[1] + ')');`

**مُثبت عملياً:** ملف درس يحتوي
`meta: (function(){ require('fs').writeFileSync('/tmp/PWNED','x'); return {}; })()`
أدّى إلى كتابة الملف على القرص أثناء «التحقق».

في خط إنتاج يستقبل ملفات مولّدة بالذكاء الاصطناعي أو مُرسَلة من مؤلّفين آخرين،
«التحقق» يصبح تنفيذاً. البديل: `JSON5`/`vm` بصندوق معزول، أو `new Function`
داخل `vm.runInNewContext` بسياق فارغ ومهلة زمنية.

## نظام اللقطات

أُضيف `tools/snapshot.sh` لأخذ صورة كاملة للمشروع قبل وبعد أي عمل.

```bash
tools/snapshot.sh create "وصف" [--keep]   # لقطة (--keep = محمية من الحذف)
tools/snapshot.sh list                     # عرض
tools/snapshot.sh diff    <id>             # الفرق عن الحالة الحالية
tools/snapshot.sh restore <id> [--clean]   # استرجاع (لقطة أمان تلقائية أولاً)
tools/snapshot.sh prune   [n]              # تنظيف
```

الضمانات:
- اللقطات في `.snapshots/` (مستثناة من Git عبر `.gitignore`).
- `restore` لا يمسّ `.git` إطلاقاً — تاريخ Git يبقى سليماً.
- `restore` يأخذ لقطة أمان تلقائية قبل التنفيذ، فحتى الاسترجاع الخاطئ قابل للتراجع.
- `restore` يُنفَّذ من نسخة مؤقتة من السكربت حتى لا يُعيد كتابة نفسه أثناء العمل.
- اللقطات المحمية (`--keep`) لا يحذفها `prune`.

تحقُّق مُنفَّذ: تعديل ملف + إضافة ملف + حذف ملف → `diff` رصد الثلاثة →
`restore --clean` أعاد المشروع إلى تطابق تام.
